# MiroFish-derived upgrade: review package

Prepared 26 September 2026. Version 2.0 review candidate.

The user now authorizes direct inspection, reuse and adaptation of MiroFish, and reports permission from its team. The intended project is a noncommercial upgrade that preserves MiroFish's material capabilities and adds demonstrated improvements. This replaces the independent-reimplementation strategy in `_rebuild_plan`.

No application source, remote repository, branch, PR, workflow or release was created by this planning turn. This package is the concrete proposal for review before execution.

- [Master plan](MASTER-PLAN.md): product, architecture, phases, migration and acceptance.
- [Capability and reuse register](CAPABILITY-REGISTER.md): mandatory parity and improvements, source locations, evidence requirements.
- [GitHub delivery and README specification](GITHUB-DELIVERY.md): branches, commits, PRs, CI/CD, releases, exact reference presentation.
- [Orchestration protocol](ORCHESTRATION-PROTOCOL.md): main/worker responsibilities, dispatch and acceptance template.
- [Evidence and decisions](EVIDENCE-AND-DECISIONS.md): attachment review, archive identity, inspected implementation, current external sources and limitations.

Recommended working identity: **MiroFish Research Lab**, repository candidate `desanv01/mirofish-research-lab`, initially private. These names/visibility remain proposals, not created resources or a claim of upstream endorsement.

Execution principle: establish the complete inherited baseline, patch its risks, introduce controlled seams, and improve one capability at a time. A weaker replacement cannot become the default merely because its architecture is newer.
