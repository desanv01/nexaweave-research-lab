# Scoped graph pages (U03c foundation)

`GraphitiKnowledgeProvider.page(scope, request)` enumerates one graph kind at a time: node, edge, or episode. The strict v1 request allows a page limit from 1 to 100 (default 25), an optional cursor, and a node-only entity type label filter. The result holds existing `FactResult` values and an optional next cursor. This is a read-only operation: it does not call extraction, embeddings, model search, or graph mutation.

The provider selects fixed Cypher for each kind and binds the derived group ID, exclusive last UUID, `limit + 1`, and optional node type. Edges must have the requested relationship group and both endpoint groups. Returned rows are checked again for scope, canonical UUID identity, ascending order, and filter match before they become facts. Existing episode/evidence decoration verifies provenance and refuses incomplete markers. Embeddings and internal projection fields are excluded from returned attributes. A page above 1 MiB serialized UTF-8 fails with a stable error instead of silently dropping facts or evidence.

The cursor is URL-safe base64 JSON containing version, exact group ID, kind, node filter, and last UUID. It is bounded and strictly parsed, including duplicate-key rejection. It is navigation data, not an authorization token. It deliberately does not bind page size, so clients may change limits. Pages are live database views: concurrent graph mutations can change later pages. There is no snapshot or historical consistency claim.

The raw provider still assumes an already-authorized scope. A future application service must enforce ownership, tombstone state, and uncertain-write barriers before exposing graph reads. This library method is not permission to expose the raw provider publicly. U03c adds no Flask route, transport, mutable lifecycle method, reconciliation, or semantic fallback.

Pure fixtures exercise cursor and request rejection before driver access, page boundaries, ordering and provenance failures, scope and endpoint checks, projections, and the result budget. The disposable Neo4j fixture uses synthetic model collaborators, two scopes and multiple pages. It compares every paged UUID set and count with direct scoped queries and checks that a uniquely identified cross-scope fixture edge is excluded, then removes that edge. Main owns execution and acceptance.
