# Entity metadata preservation (U03f)

`FactResult` v1 now carries bounded `labels`, `summary`, and `expired_at` fields. They are additive defaults, so older facts without the fields still deserialize. Labels are a tuple of at most 64 distinct nonempty strings, each at most 128 characters and without control characters. Summary is optional and at most 32,768 characters. Expiry is optional and timezone aware. Invalid or oversized values fail validation; none are truncated. These response fields do not change the source, ontology, or operation fingerprint.

Node labels and summary flow from Graphiti ingestion/search objects and from Neo4j page/detail reads. Page and detail reads use `labels(n)` as the label authority even if a `labels` property exists on a node. Each adapter requires a list or tuple label container before conversion and rejects more than 64 entries. A missing Graphiti object label attribute defaults to empty; an explicit `None` or malformed container fails. A node's absent summary stays `None`; an empty stored summary stays empty. Edge `expired_at` is preserved separately from `valid_at` and `invalid_at`, with Neo4j temporal values converted to native datetimes before DTO validation. The explicitly represented fields are excluded from generic attributes, as are embedding arrays; other existing custom attributes remain available.

The page and command boundaries retain their existing provenance, scope, identifier, fact-count, and byte limits. A copied DTO that bypassed Pydantic construction is revalidated at those boundaries. Labels are metadata for inherited population selection and are never authorization. Expiry is metadata, not a claim that historical queries or temporal filters now work.

This slice does not connect the inherited Flask readers, provide ownership checks, reconcile uncertain writes, or guarantee a consistent snapshot across live graph pages. Main owns execution of the pure and disposable Neo4j fixtures and later application integration.
