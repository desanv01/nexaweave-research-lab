# Connected report follow-up turn

This adapter starts from a completed, freshly authorized connected report. A plan binds its exact report receipt, manifest, full report digest, source/native context, question, language, completed-history head and five-pair prompt projection. Planning is model-free. A new turn may start only while the planned history head is still current and no other turn owns the report. Repeating the same turn ID and fingerprint recovers its existing journal row. Distinct IDs cannot bypass the active claim.

The PostgreSQL `mf_followup` schema owns the turn journal and scoped completed chain. Admission locks the report history and the same `mf_execution.accounts` row used by knowledge, preparation, native and report work. The fifth receipt purpose `connected_followup_budget_v1` has a separate episode/fingerprint and settles the full immutable ceiling; it is not a billed-cost measurement. Unknown request or cleanup retains that ceiling. A known closed failure may release only the active report claim, keeping uncertain spending reserved. Completion updates the immutable result, budget reservation and history head in one transaction. A restarted host reads the journal and never redispatches a partially owned model turn.

The owned child copies the validated parent report files into a private ReportManager root, runs the inherited `ReportAgent.chat` ReACT loop, and writes six separate turn artifacts. It cannot modify the accepted parent report directory. The child records executed source/native tools, not model-proposed tool text. Source/native markers are checked against the frozen admitted reference set; reference integrity does not establish semantic support. Report prose and prior answers are hash-bound context, not new citation authority.

`conversation.json` includes the exact full question and answer of every completed turn through this turn. Earlier pairs carry their final receipt/head proof. The current last pair intentionally carries null receipt/head fields because its receipt hashes the manifest that hashes this file. The final current proof lives in the completed journal/common result/read. The next turn's new snapshot fills this turn's proof as prior history; earlier artifacts are immutable. The model prompt separately admits only the latest five pairs and at most the first 4000 characters of each answer. Before shared-budget admission, the service serializes the exact next conversation shape and reserves worst-case escaped answer space within 2 MiB.

Protected `plan`, `start`, `status`, `cancel`, `read`, `download` and paged `history` operations use the existing token/origin boundary and cold route registration. Reads validate every artifact descriptor/hash and fresh parent source/native authority without model construction, runtime polling or budget mutation. History pages use completed journal proofs and allow older completed turns to remain readable after a newer head. The available output labels expose the bounded complete conversation export and the distinct model prompt projection.

The static source and authored tests are **unverified until Main runs its owned local, PostgreSQL/Temporal, browser and hosted gates**. This adapter does not establish live model determinism, semantic support, actual billed cost, or full-project acceptance.
