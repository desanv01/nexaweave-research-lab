# Provider-neutral inherited investigative reports

The internal trusted construction entry point is `KnowledgeReadFacade.report_agent(graph_id, simulation_id, simulation_requirement, model_client=..., search_selector=..., interview_capability=...)`. This source-only slice requires the host's configured display graph **and `layer="source"`**. It constructs the real `ReportAgent` with one accepted bounded node/edge projection. The injected model object must expose the inherited `chat` and `chat_json` methods. This change adds no HTTP route, live model bootstrap, model budget, or network search adapter.

The neutral `KnowledgeReportTools` subclass runs inherited InsightForge subquery decomposition, entity relationship chains, Panorama temporal classification, QuickSearch, statistics, and context assembly. It overrides their graph primitives with the captured projection. No Zep client, SDK, retry helper, or lexical fallback is used in neutral mode. The explicit semantic search capability receives the bound graph ID, full bound scope, query, scope (`edges`, `nodes`, or `both`), and result limit. It must return at most that many distinct selections shaped `{id, kind, score, bound_scope}`. IDs must exist in the captured projection, scope and kind must agree, and scores must be finite numbers. The adapter resolves all fact text, node summaries, temporality, episode IDs, and evidence IDs from the captured projection. Model-authored fact strings are never accepted as search results. Missing semantic search is `unsupported`.

Interviews have a separate simulation binding. Without `interview_capability`, the interview tool is `unsupported`; a wrong simulation ID is rejected before invocation. An injected interview result is a trusted external capability result, not proof that native OASIS interview IPC has been connected or qualified. Source graph edges are labeled as source evidence in neutral tool text and are not described as observed simulation actions or opinions.

`ReportAgent` still plans a multi-section outline, performs repeated research calls for each section, reflects through the inherited ReACT loop, writes sections and the assembled Markdown, tracks progress, and supports follow-up chat. Neutral failures do not invoke legacy fallbacks or complete an ungrounded report. Provider and callback errors pass through fixed allowlisted codes in failed state, logs, and outward tool/chat failures. The report directory contains `retrieval_evidence.json`, a bounded sidecar with the bound graph/simulation IDs, full source scope, projection fingerprint, selected IDs and scores, direct projection and node-detail reads, episode/evidence IDs, and capability limitations. Repeated direct reads are deduplicated. A fresh follow-up agent validates and loads that sidecar before calling the model, pins the report ID for the whole chat, and appends new retrievals. Same-process updates are serialized; a changed sidecar or report during a call fails without overwriting it. This ledger records what was retrieved; it does **not** validate citations for each generated claim.

The projection is bounded by the accepted reader, but a live read spanning pages is not a global transaction snapshot. The sidecar's in-process lock and conflict check do not provide a cross-process compare-and-swap guarantee. The inherited local report files and progress are not an atomic publication or durable job system. There is no live semantic adapter, native interview acceptance, claim-level citation verification, or live model quality evidence in this phase. Offline scripted selections show wiring and algorithms only; full U03/U09 acceptance remains with later integration gates.
