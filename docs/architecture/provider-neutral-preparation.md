# Provider-neutral inherited simulation preparation

The internal trusted entry point is `KnowledgeReadFacade.preparation_dependencies(graph_id, chat_client=..., model_name=..., base_url=...)`. It accepts only the host's configured display graph, obtains the accepted bounded `KnowledgeGraphReader`, and binds real `OasisProfileGenerator` and `SimulationConfigGenerator` instances to an injected chat client. Pass the result to `SimulationManager(preparation=dependencies, simulation_data_dir=trusted_root)`, then use the inherited `create_simulation` and `prepare_simulation` methods. No public paid endpoint is added. The caller owns model transport, local secrets, and a concrete spending cap; this integration makes no such policy decision.

The helper reads one bounded projection through the accepted reader. The manager filters typed entities from that same projection using the reader's filtering rules; persona context and `source_grounding.json` derive from its incident facts, neighboring node summaries, and episode/evidence IDs. A callback failure has no Zep fallback. The resulting rich persona text and generated activity configuration are model output and assumptions; grounding references must not be treated as generated source facts. This removes mixed provenance within one preparation, but the read spans node and edge pages and is not a global graph transaction snapshot. Graph changes during that scan remain a provider consistency limit.

The inherited preparation lifecycle and progress callbacks remain in use. For enabled platforms, the manager writes native `reddit_profiles.json` and/or OASIS five-column `twitter_profiles.csv`, then `simulation_config.json`, `source_grounding.json`, and `state.json` under its safe simulation directory. Neutral mode rejects truncated, malformed, or incomplete model JSON without invoking inherited repair or synthetic fallback. It checks profile count, order, source IDs, configuration correspondence, enabled platform configuration, and required output files before marking READY. Failed or partial generation records `preparation_failed` and remains FAILED. Legacy callers continue to construct `SimulationManager()` with the historical behavior.

Current limitations: The manager still uses its existing local JSON/CSV/state persistence rather than durable jobs or atomic multi-file publication. The neighborhood callback is a bounded graph projection, not a search service. Scripted offline clients can qualify wiring and file shapes but do not establish live model quality, native OASIS loader compatibility, engine execution, or a production paid-call cap. Those gates remain with Main.
