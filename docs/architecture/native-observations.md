# Completed native recorded observations

The protected research-local `POST /api/native-observations/page/<graph_id>` is an explicit read of completed owned native output. It does not start, recover, cancel, register, poll or ingest runs, construct models, or reserve/settle ledger entries. The optional trusted operator injects `NativeObservationsFacade(settings, host=NativeObservationsHost(launch_host=existing_host))` into `create_app(native_observations_facade=...)`. A cold research-local host returns `observations_unavailable` (503); graphiti-readonly does not register the route. Existing token, source-scope, Origin and CORS guards apply.

The exact 4 KiB request has `schema_version`, canonical `launch_id`, lowercase `launch_sha256`, selected `platform`, integer `offset` (0–10000) and integer `limit` (1–20). The browser never supplies directories, receipts, providers, principals or projects. Query parameters, encodings, nonfinite numbers, duplicates and extra fields are refused. Four facade calls may run concurrently; admission is released even on exceptions. Responses are finite 256 KiB plus a 128-byte envelope with no-store/nosniff headers and code-only errors.

Before filesystem access the host reads the frozen launch and current owned preparation, source and project revision, then requires a permanently claimed completed launch and exact authoritative native request/receipt/owner/attempt/child identity. It verifies READY inputs using the existing preparation artifact validator. Output root is derived solely from trusted preparation root and operation UUID. Reauthorization follows output reads, with a second READY input verification, before the reader rechecks all held output descriptors and ancestors.

The complete existing launch status DTO is validated by the unchanged U07d wire validator. Its authorization flag uses the existing configuration inspection (no backend factory invocation); generation may be disabled while reads remain available. Cleanup is honestly unknown because obtaining local cleanup status would poll runtime. Dynamic authorization/cleanup fields need not equal a previously displayed status snapshot; frozen identity and completed receipt do.

Output manifest order is the selected platform order, with `<platform>_simulation.db` then `<platform>/actions.jsonl`. The exact canonical sorted compact ASCII manifest SHA must match native receipt evidence. Databases are hashed as bytes; no SQLite connection/query occurs. Files must be regular single-link files, with no symlink, junction or reparse point, inside a trusted absolute root. Initial path-to-descriptor binding compares common device/inode/size identity and requires a single link in both APIs. Full device/inode/size/nanosecond mtime/ctime/link identity remains stable within each same API and is rechecked finally; ancestor directory identities remain bound. All handles close even on malformed evidence, races or authority failure.

Existing 64 MiB output and 256 MiB aggregate limits remain. Every selected action log additionally admits at most 8 MiB, 10000 physical records, 8192 UTF-8 bytes per line and eight container levels. Empty files and one final newline are allowed; blank lines, nonobjects, duplicates at any depth, nonfinite numbers, invalid UTF-8 and lone surrogates are rejected. Bounds return `result_too_large` (413); malformed/missing/changed/mismatched evidence returns `evidence_invalid` (502). Nothing is truncated, deduplicated, sorted or omitted.

`raw_json` is the complete original UTF-8 physical line without its LF/CRLF terminator. Its SHA hashes those exact bytes. Parsed values are used only for strict admission and full-log counts. Numeric lexemes (including `1.0`, exponents, negative zero and large integers) remain visible unchanged. Counts describe records containing string `event_type`/`action_type`; success/failure use strict boolean values on action records. They do not represent unique actions, users, billed calls or simulation-end totals. Unknown records remain visible. Offset equal to total returns an empty page; offset beyond total is invalid.

Every count category must be at least its displayed-page count. Its full-log count minus displayed-page count cannot exceed the number of undisplayed records. Whole-log pages additionally require exact count equality. These checks reject impossible partial-page counts even when all record, file, manifest and receipt hashes are valid.

Auth failures, stale/tombstoned source/project, incomplete launches, unselected platform and identity conflicts are refused before file reads. Error payloads never contain exceptions, paths, SQL or model data. Pure tests use handcrafted bytes only for parser/transport negatives. Marked PostgreSQL tests prove actual authority denial ordering. The separately marked connected engine fixture creates fresh inherited READY files and real PG/Temporal/OASIS two-platform output before proving page/digest/count isolation and byte/ledger preservation with model generation disabled. Its graph projection is the existing source-grounded fixture; actual Neo and browser qualification remain Main-owned.

The five actual PostgreSQL authority cases and lazy `pg_factory` reside in `services/knowledge/tests/test_native_observations_authority.py`, whose only top-level import is pytest. App, backend API fixture helpers and store imports occur inside the selected test body. Generic `backend/tests/test_native_observations_host.py` retains the unchanged 25 pure host cases. This placement keeps generic offline collection independent of PG setup and services test paths; it adds no skip, ignore, fake SDK or default selection change. Main's dedicated runner must still select all five PG cases with zero skips, all 106 observation unit cases and the separate fresh native engine case.

Integer and fractional/exponent tokens share finite IEEE754 admission, matching browser parsing. Unsafe-but-finite integers remain inspectable literal evidence; an integer overflowing to Infinity is rejected. Actual LF/CRLF terminators are removed before record admission; any remaining literal CR/LF is invalid, while escaped backslash-r/n is preserved. Path-to-descriptor binding compares common device/inode/size/single-link identity because Windows lstat/fstat timestamps can differ; full timestamp stability is compared within each same API, with both path and descriptor rechecked finally.
