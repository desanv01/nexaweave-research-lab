# Internal knowledge command boundary (U03d)

`KnowledgeCommandDispatcher` is an in-process, versioned command contract between a future trusted application transport and the isolated knowledge runtime. It opens no listener, reads no credentials, and initializes no provider. The host injects the provider, ledger-backed ingestion coordinator, and mandatory async authorization callback. A caller principal is supplied out of band by that trusted transport and never taken from client JSON. This module does not authenticate a principal or infer ownership from a graph group ID.

Requests are UTF-8 JSON capped at 512 KiB and 32 container levels. The root has exactly `version`, `request_id`, `method`, `scope`, and `payload`. Version is integer 1; `request_id` is a canonical lowercase UUID. The complete `KnowledgeScope` JSON is required. Payloads are the existing strict DTOs for `page` and `search`, a canonical provider UUID for `entity`, and exact source plus ontology DTOs for `ingest`. Duplicate JSON keys, unknown fields and methods, nonfinite constants, malformed types, and invalid identifiers fail before policy or provider work. A valid request ID is echoed in error replies once the root identity is verified; malformed roots use null.

After validation, `authorize(principal, method, scope)` must return literal `True`; every other result or callback error denies access. The host policy must check ownership, lifecycle tombstones, uncertain-write read barriers, and any other application rule. The dispatcher does not supply those rules. It admits at most `max_inflight` active calls without a queue, counting authorization and execution. The counter is for one asyncio loop instance only; it is not cross-thread or distributed admission. Authorization and read calls share a finite cooperative monotonic deadline, with a post-await check for callbacks that suppress cancellation. Python cannot forcibly stop a blocking native or noncooperative remote operation.

`page` routes to `provider.page`, `entity` to `provider.entity`, and `search` to `provider.search`. `ingest` routes only to `coordinator.ingest`; there is no direct provider ingestion path. Search and ingest are disabled by default even after authorization. Setting `allow_model_calls=True` is trusted host configuration and is not evidence of provider credentials, monetary budget, or spend authorization. A production host must impose its configured provider policy and monetary cap before enabling paid calls. The dispatcher does not add a timeout or retry around ingestion that could discard the coordinator's uncertain-write safeguards.

Replies are UTF-8 JSON capped at 2 MiB, with exactly `version`, `request_id`, `ok`, and either `result` or `{error: {code}}`. Error codes are allowlisted and contain no exception message, traceback, input, path, provider response, or credential. `page` must return `GraphPage`; `entity` and `search` must return `SearchResult`. Successful graph results are revalidated for scope, canonical identifiers, finite scores, fact-count limits, and serialized size. An ingest result contains only the validated durable `CompletionReceipt` fields: group ID, deterministic episode ID, request fingerprint, and exact source evidence IDs. An unexpected coordinator timeout maps to uncertain; caller cancellation remains cancellation even if a coordinator returns after suppressing it. The boundary does not expose attempt IDs or raw Graphiti data.

This slice has no Flask route, transport authentication, deployment endpoint, model initialization, usage reservation, reconciliation, or public provider access. Main owns transport implementation and end-to-end authorization verification in later work.
