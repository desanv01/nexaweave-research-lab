# Connected native narrative reports

NexaWeave connects a completed, owned native receipt to the inherited ReportAgent. The new research-local API admits a report UUID, selected launch UUID/hash, requirement, output language and optional declared native windows. Review is SDK-cold. Explicit Start performs atomic report dispatch admission against the same shared account capacity used by ingestion, preparation and native execution.

The optional `connected_report_facade` passes through `create_app` and `create_read_app`. An absent trusted host returns `report_unavailable`; it never constructs a provider. `ConnectedReportFacade.execute(method, graph_id, payload)` handles six explicit POST routes. `known_report(graph_id, payload)` supplies durable download metadata without invoking recovery, model or budget operations. The existing token/origin boundary remains authoritative.

Generic `research_local` HTTP startup, health and non-report routes remain cold with respect to `mirofish_execution`, `mirofish_storage` and provider SDKs. Report route registration also stays cold: it defers the shared codec and optional facade until an actual report operation is handled. To serve report operations, a separate HTTP interpreter needs the local `services/knowledge` distribution installed non-editably with `--no-deps`; a missing pure contract package yields a fixed `report_unavailable` envelope for that operation without preventing unrelated HTTP routes from starting. `mirofish_execution` has lazy optional exports and `report_contracts` uses only the standard library, so this installation does not install provider dependencies or construct a model. Main reproduced the missing-package failure under the former eager import and owns the CI/runtime-profile installation correction; the original provider-import negative gates remain required.

`DurableReportHost(settings, connection_factory, read_facade, native_launch_host, artifact_root, ...)` checks exact principal, source scope and display graph binding. `NativeObservationsHost` supplies the existing current source/preparation/native authority. `NativeObservationReader.context(...)` reads the full native manifest once and parses every physical log record even for a partial selection. Existing `page` parsing, counts, bounds and result behavior remain intact. Selected records retain physical indices, hashes, original number lexemes, field ordering, repetitions and unknown fields. Complete coverage is all-or-refuse under the smaller report context cap.

The frozen private context includes source projection, retained source text/passages, source/preparation/native binding, full native manifest and exact selected native records. Reference keys use unbracketed `source:UUID` or `native:platform:index:record_sha256`; prose uses `[[key]]`. Every admitted source passage is verified against retained text and its excerpt digest. Whole-context preflight includes the last native record. Reauthorization compares the complete frozen context before generation, first possible request, publication, read and download. Projection reads retain the inherited bounded snapshot and non-atomic read limitations; report generation does not upgrade them to live semantic qualification.

`BoundedReportModelFactory(transport_factory, model_name, limits)` is explicit trusted construction. The pickleable transport factory receives `max_retries=0` and finite timeout and returns an OpenAI-shaped cooperative transport with `max_retries == 0` and `close()`. There is no default LLMClient construction. One SDK create boundary handles every inherited direct and nested research call, forces non-streaming captured token limits and finite request timeout, bounds complete inputs/outputs and shares one counter. Provider failure and parser failure fence later requests. Before the first possible request the child requires a durable journal acknowledgment; lost acknowledgment never grants a provider retry.

`ReportProcess` uses spawn, a private operation CWD and output root. The inherited ReportManager/loggers and thread locale are bound only inside that child. On Windows the parent assigns the waiting child to the accepted kill-on-close Job before authorizing generation; Unix children establish a private process group. Initial READY and each control acknowledgement remain bounded10 seconds. READY/GO and FIRST/ADMITTED use an immediate exact `('checking', action)` acknowledgement before full synchronous reauthorization, then an exact one-element grant under the same captured absolute whole-run deadline. Child grant waits poll cancellation without constructing a transport before GO or making a request before durable ADMITTED. The grant phase never restarts the clock or skips/caches source checks. Out-of-order, duplicate, foreign, closed-pipe, denied, cancelled and expired phases refuse work; parent also rechecks after authority and durable admission before grant. Whole run remains at most the captured600-second ceiling, SDK timeout remains at most15 seconds and cleanup has one total20-second deadline. Retained owner uncertainty is not converted to known cleanup. Partial files/logs remain private and are preserved after failure.

The actual inherited outline planner, section ReACT loops, reflection paths, neutral tools and report assembly remain. Connected mode adds `recorded_native_events`, removes the unavailable interview capability from its advertised tool set, supplies output-language/evidence instructions and validates references before the inherited completion transition. Source search ranks only frozen facts by lexical matches; its separate native evidence artifact records `lexical_only`. The original retrieval evidence version-one contract and `restore_evidence` are unchanged. Neither reference integrity nor scripted generation establishes semantic support or native interview quality.

`mf_report` owns an isolated SQL migration and matching rollback, SQL checksum and complete catalog digest. Frozen identity, declaration and context hashes are checked on records. Atomic queue admission locks the current project/preparation/native rows and existing BudgetLedger account row, reuses the accepted account/totals helpers and inserts a domain-separated started reservation with the permanent report dispatch claim. A second Start or lost reply cannot create another reservation/process. Activity claim is also permanent. Expired owner state becomes uncertain; it never restarts partial model work. Cancellation persists intent and does not claim termination.

Successful report settlement accounts the whole reserved ceiling with a fourth-purpose `ReportBudgetReceipt`, containing the actual journal's completed report proof and its canonical digest. Its exact seven-field JSON is `kind`, `operation_id`, `attempt_id`, `fingerprint`, `plan_sha256`, `report_receipt`, `report_receipt_sha256`; kind is `connected_report_budget_v1`. Immutable scalar internals back detached `report_receipt`/JSON exports. The report-purpose episode uses UUIDv5/NAMESPACE_URL over `mirofish:connected-report-budget:v1:` plus scope group and report UUID. Existing source/preparation/native mappings stay unchanged. The shared parser rejects cross-domain receipt substitution, wrong attempt/fingerprint/episode and nonempty report evidence IDs. Publication, typed receipt settlement and final file-proof verification share one transaction. No null settled receipt, knowledge/preparation/native receipt fabrication or SQL constraint weakening is used. Known no-call owner cleanup may release capacity. A possible request, unknown owner or unknown dispatch retains capacity conservatively. These amounts are reservation/accounting ceilings, never actual provider bills.

`TemporalReportHost` owns a synchronous activity executor on an existing Temporal client/loop. Workflow and activity retries are disabled. History returns identifiers/state only and fixed nonretryable failure codes. `scheduler_for(owned_loop)` creates no loop or detached orchestration thread. Main composes this host and owns worker lifetime, actual combined qualification and shutdown.

Completed output order is `meta.json`, `outline.json`, `full_report.md`, `retrieval_evidence.json`, `native_evidence.json`, then one to eight section Markdown files. File descriptors, digests, sizes, link protections and ancestor identities are checked around publication/read/download. The full output manifest is checked even when a single artifact is requested. Read and download never poll runtime, reserve budget, recover owners or construct models. JSON downloads use canonical base64 and exact known manifest allowlists; the browser owns its own download URL lifetime.
