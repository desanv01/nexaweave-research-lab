# Bounded backend knowledge reader (U03g)

`KnowledgeGraphReader` is a synchronous, stdlib-only consumer of an injected `client.call(request_bytes) -> reply_bytes`. Its host binds one complete v1 knowledge scope and a separate legacy display graph ID at construction. A graph ID must match that binding on every read. The constructor copies and validates the scope, so later changes to the caller's dictionary do not alter requests. The binding identifies the intended graph; the runtime command policy must still authorize every request. This module does not create a transport, inspect configuration, or call Graphiti, Neo4j, Zep, Flask, or a model.

Each public operation sends only versioned `page` commands with a fresh request UUID, `limit=100`, and the bound scope. It validates the reply envelope, full current fact fields, provenance, labels, timestamps, and strict ordering before projecting data. JSON strings and dictionary keys must contain valid Unicode scalar values; escaped lone surrogates fail before any cursor is reused. Unknown or malformed replies and private transport exceptions become fixed `KnowledgeReadError.code` values. Known dispatcher errors remain their fixed codes. The reader never treats a failed page as an empty graph and does not retry. KeyboardInterrupt and SystemExit retain their usual behavior.

`ReadLimits` is frozen. Defaults are 200 pages, 10,000 facts, 16 MiB of total reply bytes, and a 120 second cooperative deadline per top-level method. Maximum configurable values are 2,000 pages, 100,000 facts, 64 MiB, and 300 seconds. Every individual reply remains capped at 2 MiB. Node and edge scans, plus projection and enrichment, share the same budget. The deadline is checked around each transport call and throughout projection loops; it does not preempt an arbitrary blocked callable. The concrete process client retains its own per-call deadline.

`get_all_nodes` and `get_all_edges` return complete bounded legacy-shaped dictionaries. `get_graph_data` returns graph ID, node and edge arrays, and counts. Node output includes `uuid`, display `name`, `labels`, display `summary`, `attributes`, and `created_at`. Edge output includes `uuid`, display `name`, display `fact`, `fact_type` from the name, source and target IDs/names, attributes, `created_at`, `valid_at`, `invalid_at`, `expired_at`, and `episodes`. Both outputs also retain explicit `evidence_ids`, temporal fields, provenance `episodes`, and optional `score`. Nullable names and summaries become empty strings only in these legacy projections. Labels and metadata come from explicit fact fields, never from arbitrary attributes; there is no raw-record embedding path.

`filter_defined_entities`, `get_entity_with_context`, and `get_entities_by_type` return duck-typed `EntityNode` and `FilteredEntities` dataclasses. The first custom label (excluding `Entity` and `Node`) is what `EntityNode.get_entity_type()` returns. An optional type list controls collection membership and the reported `entity_types`; it does not change `get_entity_type()`. An empty list has the inherited unfiltered meaning. Enrichment scans all edges once, builds a node map and adjacency index, and includes incoming and outgoing edges. Self-loops appear once as outgoing. Neighbor nodes have deterministic UUID order. Disabling enrichment does not fetch edges. A missing context node returns `None` only after a successful full node scan. When a combined graph contains an edge with an absent node endpoint, the reader raises `inconsistent_graph`.

Page scans are live and have no snapshot guarantee. Concurrent graph changes can therefore cause an inconsistent graph or ordering error; the reader fails rather than presenting partial complete context. This slice does not rewire application routes, implement graph ownership, provide a read barrier, or claim full inherited workflow parity.
