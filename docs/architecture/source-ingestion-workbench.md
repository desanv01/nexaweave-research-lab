The existing source inspector emits the explicitly inspected, digest-validated retained DTO. Retention receipts and source lists do not enable ingestion. Closing inspection, starting another inspection or retention, disconnecting, auth denial and reset invalidate the selected source and discard ingestion state. Sources, research and dossier reads retain the private parent client, shared cancellation and busy state.

The ontology editor is a local editable starter: Person, Organization and WORKS_FOR. It is not a generated semantic ontology. Visible controls support entities, relationships, typed attributes and selected source/target pairs. Local bounds are ten entities, ten relationships, five attributes per type and ten pairs per relationship, below the API limits. ASCII identifier, duplicate, reserved entity/attribute, typed attribute, description and pair checks apply before the Plan request. Removing or renaming an entity requires correcting any affected relationship selections. No contract JSON, scripts, provider secrets, account or cap are entered in this UI.

Correction 1 adds field-specific EN/ZH/MS ontology errors and a linked, focusable summary after an explicit invalid Plan. Name/description rules are shared with the strict DTO validator. Stable per-row control IDs stay outside ontology payloads and survive sibling removal. Invalid controls use `aria-invalid` and `aria-describedby` to associate localized inline errors. The summary links name the type/attribute/pair field and focus its control when activated. The invalid Plan creates no request and preserves entered values. Once validation has been activated, field errors update as users correct the draft without moving focus on each edit or blur. Successful validation clears the summary before requesting a new immutable plan; connection/source reset clears it too. Relationship references are never silently reassigned after entity renaming/removal. Native required validation remains in place alongside explicit strict validation.

Only an explicit Plan action creates fresh operation/ontology UUIDs and snapshots the retained revision and ontology. The client revalidates the full inspected source before transport. Planning requires 1–32768 retained codepoints and at least one declared nonempty passage. Planning makes no model calls and reserves no budget. Source text and passage order are preserved exactly.

The first returned source scope is an authenticated server assertion. The browser independently knows the inspected source project/revision/digest, but does not independently know the operator's workspace UUID or internal graph UUID. It checks source-only layer, null run/branch, canonical UUIDs and matching inspected project, then freezes all scope fields in the client for subsequent plan/execute/status replies. The protected backend remains authorization authority; the UI does not prove initial workspace or graph ownership. Manual recovery uses the same server scope and checks a known inspected project when present, without inferring a source revision association.

Canonical fingerprint is SHA256 of recursively key-sorted compact JSON `{scope, source, ontology}`. The full SourceEnvelope includes version, retained source revision/hash/name/content, ontology revision, operation, document kind, recorded timestamp, null asserted-valid time and evidence IDs in stored order. Timestamp conversion preserves six fractional digits without JavaScript Date rounding and normalizes only UTC `+00:00` to `Z` (Pydantic omits zero fractions). Main supplied two actual installed typed golden vectors covering Unicode, CRLF, microseconds and a nonzero timezone. Deterministic group is `mf1_` plus SHA256 of sorted scope excluding schema_version; deterministic episode uses UUIDv5 URL namespace and `mirofish:episode:v1:<group>:<operation>`.

The immutable review shows the operation, episode, fingerprint, ontology revision and evidence IDs alongside the still-visible selected source and frozen ontology editor. Execution requires a separate acknowledgement and Execute button. The component latches the exact planned attempt synchronously before its sole POST. Submitted ontology controls remain disabled. Every submitted error, cancellation, timeout, lost reply, default-off denial or malformed response retains reconciliation identity and permits only explicit status reads for that attempt. No automatic retry or polling occurs. Source changes clear old state; any late reply from a previous epoch is ignored.

GET operation recovery strictly validates fixed keys, types, flags, identities, evidence and receipts. Known-attempt status requires matching scope, operation, episode, fingerprint and ordered evidence; manually recovering that same operation cannot weaken those checks. A manual unknown operation has no source association. A missing status/404 is unknown, not proof of no effects. Graph and admission states are displayed separately, including completed graph with uncertain admission and started admission with not-admitted graph. Actual charge and model calls remain unknown. A settled admission ceiling is not a guaranteed bill; released admission or cancelled state does not establish graph rollback. Numeric ceilings outside JavaScript's safe-integer range are rejected instead of rounded, a conservative browser compatibility limit below the backend signed-64-bit bound.

The client uses existing loopback origin and bearer constraints, `credentials: omit`, no redirects, no referrer and `cache: no-store`. Ingestion response streams are bounded to 256 KiB plus envelope allowance; duplicate JSON keys, extra fields and non-JSON replies are rejected. Unauthorized bearer or origin denial clears the connection and parent protected state. An old read-only host's non-JSON 404 maps to safe source unavailability. Only fixed localized messages are rendered; user/source text is literal interpolation. The UI never configures host execution flags or paid credentials.

Credentials, source/draft/files/operation state and results remain private in memory, with no storage, URL or clipboard persistence. Reload/unmount clears the workflow. Users must retain operation ID independently before execution, and manually enter it for recovery after reconnect. Locale changes translate current state without causing requests or resetting a submitted latch. The supplied component tests use actual SFC scripts/templates, private API modules and jsdom; authored style/accessibility assertions are not browser proof of contrast, layout or assistive-technology behavior.
