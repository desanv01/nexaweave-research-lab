# One-shot knowledge runtime pipes (U03e)

The backend's `KnowledgeProcessClient` is a standard-library-only parent for one command to one isolated Python child. The child host injects the accepted `KnowledgeCommandDispatcher`, authorization policy, and out-of-band principal into `serve_once`. This slice does not create that production bootstrap, initialize Graphiti, load credentials, open a listener, or add a Flask route. One child handles one request and one response through inherited private stdin/stdout pipes.

Each frame is a four-byte unsigned big-endian length followed by UTF-8 JSON. Requests are limited to 512 KiB and replies to 2 MiB. Both sides reject zero or excessive lengths before buffering, partial frames, trailing bytes, duplicate JSON keys, nonfinite constants, non-object JSON, malformed UTF-8, and container nesting beyond 32 levels. The parent validates exact request root fields, version, canonical request UUID, known method, and object scope/payload before spawn. The dispatcher remains authoritative for nested DTO validation and authorization. The parent accepts only a reply with the same request UUID, strict success/error shape, and an allowlisted error code. Extra stdout logging corrupts the frame and is rejected.

`KnowledgeProcessClient` takes absolute trusted interpreter and bootstrap paths at host construction, never in a request. The bootstrap leaf must be a regular `.py` file without a symlink/reparse leaf. A POSIX virtualenv interpreter symlink is allowed if its resolved target is a regular executable; the original path is used for invocation so the virtualenv remains selected. These paths grant execution of trusted code and are not a sandbox. The child receives only a minimal operating-system environment plus explicitly supplied `KNOWLEDGE_` variables, a unique temporary cwd/home/temp, and disabled Graphiti telemetry. Ambient provider keys, proxies, `PYTHONPATH`, and working-directory dotenv are not inherited. Environment scrubbing is not a network sandbox; the future host must decide credentials and network policy.

The parent uses `[python, -I, -u, bootstrap.py]` without a shell or request-driven arguments. Dedicated writer and reader threads prevent a blocked pipe from stalling the other direction. A nonblocking per-client lock rejects a concurrent call immediately. One monotonic deadline after spawn covers the write, full reply, EOF, and process exit. Every exit path stops only the owned child, closes its pipes, joins its threads as far as the OS permits, removes its temporary directory, and releases the lock. Process startup and native teardown are not mathematically hard deadlines. This lock is not distributed admission or a replacement for the ledger.

Before spawn, malformed requests raise `KnowledgeInvalidRequest` with `code="invalid_request"` and `outcome_unknown=False`; a busy client raises `KnowledgeBusy` with `outcome_unknown=False`. A spawn or temporary-directory creation failure is a fixed `transport_failure` with `outcome_unknown=False`. After a child is spawned, timeout, broken framing, EOF, a mismatched/null reply ID, nonzero exit, invalid reply, thread-start failure, or temporary-directory cleanup failure raises `KnowledgeTransportFailure` with `code="transport_failure"` and `outcome_unknown=True`. Public exception text contains no stdout, stderr, input, path, or environment value. There is no automatic retry or inference that a mutation did not happen. The application must inspect durable operation state after losing an ingestion reply. `KeyboardInterrupt` and `SystemExit` propagate after owned cleanup even when cleanup itself fails.

`serve_once` uses blocking reads on its private child pipes and returns `"replied"` or `"invalid_request"` for a host wrapper. On malformed framing it writes a bounded safe invalid-request reply with null request ID; the parent deliberately treats that mismatch on a valid request as unknown transport outcome. If the dispatcher raises or is cancelled, the child library sends no success response. It does not close caller-owned streams or call `sys.exit`. This is not an asyncio multiplexed server.

The test sources use only synthetic children. Main will choose a production bootstrap, real injected policy, lifecycle read barriers, monetary budget and provider configuration, and deployment isolation before application integration. The transport does not authorize a caller by itself and does not claim exactly-once execution or protection against hostile native code/descendant processes.
