## Contracts and assumptions

The request is schema v1 with canonical UUIDs, exact stored project revision,
bounded simulation ID, digest declarations, platform set, signed 64-bit seed,
and 1–24 rounds. The host computes and verifies artifact digests separately.
The coordinator is synchronous and accepts only a trusted injected driver. Its
dispatch callback defaults OFF. It never creates a provider or chooses a user
supplied command. `NativeSimulationSession` must retain its own exclusive
fresh-start marker in the future production driver.

Only the atomic `declared → starting` DB transition grants launch permission.
The owner, attempt, lease and child identity are durable. Expired leases become
permanently uncertain; matching terminal receipts are recoverable and
idempotent. Cancellation intent is not termination proof. Ambiguous launch or
acknowledgement attempts a conservative uncertainty fence; if PostgreSQL is
unavailable, expiry/reconciliation must complete that fence. No restart,
takeover, PID-based kill, checkpoint recovery or budget release is supplied.

The native migration depends on `mf_app.project_revisions` already existing.
It uses a separate catalog checksum and does not touch the accepted budget
migration. The integration tests import the existing guarded disposable port

child it created in a temporary directory. The test runner scrubs environment
and fails if its opt-in PostgreSQL suite skips.
