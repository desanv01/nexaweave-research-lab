## Behavior and assumptions

The simulation directory is trusted caller configuration but its entry may
not be a link/reparse point. IPC descendants are resolved beneath it with
`safe_path`. Command IDs keep the portable legacy character set and are
bounded to 123 characters to leave room for `.json` under the shared
128-character component bound. JSON is limited to 1 MiB of UTF-8 bytes,
including Unicode bytes, and 64 nested JSON containers counted from the root
at depth 1. Outbound depth validation uses decoded serialized JSON, including
tuple arrays. Invalid command candidates are skipped without
deletion; invalid response candidates remain until a valid response arrives
or the command times out. Status writes and messages use same-directory
`.tmp` files and atomic replacement. Regular-file checks refuse FIFOs before
bounded reads. Both response and command paths are checked before publishing
a response. Excessively nested inbound JSON and outbound values yield
invalid-message errors. Test fixture text IO specifies UTF-8 explicitly.
The independent cleanup behavior
accepted in U01b remains.
