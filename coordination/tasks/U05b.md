## Contracts

1. Frozen bounded wire DTO: schema version, principal, display graph ID, source
   revision UUID, operation UUID, account UUID, ontology revision UUID, positive
   microusd ceiling, explicit request fingerprint. Canonical deterministic workflow
   identity based on owned operation/account plus semantic request digest. No
   secrets, DSNs, source text, arbitrary paths, callbacks or full ontology payloads
   in Temporal inputs, memo, heartbeat, result or search attributes. SDK type
   hints alone aren't validation: revalidate on workflow/activity/host boundaries.
   Principal is trusted host identity, not an authorization grant from arbitrary
   workflow input. The existing bridge rechecks actual resource ownership.
2. Host injects a revision-bound ontology resolver and BudgetedIngestion. Resolver
   runs only inside activity, verifies requested revision and freshly computed
   bridge plan fingerprint before dispatch. No latest-ontology substitution. If
   this requires private plan access, accept a separately injected trusted
   SourceIngestionBridge used only to plan, not another arbitrary provider.
3. Workflow does no database/network/filesystem work. It invokes one real activity
   with finite schedule-to-close/start-to-close/heartbeat timeouts and explicit
   RetryPolicy(maximum_attempts=1); no workflow retries or reset/reexecute API.
   Preserve recorded completion on replay. Busy/uncertain/failure are nonretryable
   and must remain visibly distinct from completion. Cancellation is NOT proof
   that no model write happened and never authorizes releasing ledger funds.
4. Async activity maintains bounded heartbeat status using fixed codes and opaque
   identity only, propagates asyncio cancellation into accepted service, cleans up
   heartbeat task. Graceful worker shutdown is bounded, not detached execution.
   Never put model/DB calls inside workflow or hold locks over awaits. Accepted
   ledger remains source of reservation truth when Temporal acknowledgement is
   lost. No retry just because Temporal activity timed out or worker disappeared.
5. Use fixed allowlisted outward errors; strip nested exceptions/causes and secret
   text before SDK failure serialization. No repr(raw exception), payload text or
   credential logs. Validate receipt shape/identity before returning plain safe
   receipt DTO; reuse accepted receipt validators in activity, not workflow import.
6. Host helper constructs actual Worker for workflow+activity with explicit queue,
   bounded concurrency/graceful shutdown. Model dispatch gate defaults OFF even
   with injected service; qualification explicitly uses fake providers. No paid
   enablement helper. Require explicit trusted server client/queue; don't connect
   to cloud/default env automatically. Offline workflow imports remain SDK-only.
7. Start helper rejects duplicate running/completed workflow IDs rather than
   silently USE_EXISTING with a different payload. Provide separate status/result/
   cancel helpers pinned to known workflow/run identity. Completed saved result
   remains readable. Do not claim these are multi-tenant HTTP authorization.
8. Query reports workflow-known stage; distinguish requested cancellation and
   terminal result from authoritative budget status. No fabricated percentages or
   claim that worker loss safely resumes side effects.
