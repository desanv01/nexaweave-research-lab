## Required contract

- Accept already-authorized KnowledgeScope, SourceEnvelope and OntologySpec.
  Revalidate copies and the matching revision/hash before database access.
  Reject duplicate evidence IDs instead of creating a ledger receipt that
  cannot complete. Use the exact accepted request_fingerprint canonical form.
- Async ingest coordinator with explicit injected ledger/provider; no implicit
  construction of cloud clients, credentials, migration or initialization.
  Keep blocking synchronous ledger transactions out of the event loop using
  bounded offload; clearly handle cancellation during an offloaded claim (it
  may have committed even if its awaiting coroutine was cancelled). Never
  automatically release admission based on cancellation/timeout/heartbeat.
- Admit immutable operation then claim. Completed identical requests return
  the persisted receipt WITHOUT another Graphiti dispatch. Pending claims may
  race: exactly one wins ledger admission; busy/uncertain/cancelled states must
  not dispatch. Do not sleep/retry internally on busy or conflict.
- Provider dispatch happens only after claim transaction commits. No SQL
  transaction spans an await to the provider. Do not expose a bypass path for
  this coordinator; legacy raw provider is still a spike, not public service.
- Validate provider result episode ID and every fact's scope/evidence before
  acknowledgment. More importantly, obtain a read-only provider completion
  proof: matching episode scope, full request fingerprint, source content/hash,
  complete marker and exact source evidence IDs. Partial/missing/mismatched
  markers fail closed. Reading proof must never call add_episode/model APIs.
  Use fixed parameterized Cypher, validate model_copy bypasses, and preserve
  existing provider tests. Proof is for active attempt success, not a generic
  uncertain-to-completed unlock API.
- A bounded metadata-only CompletionReceipt is the durable return value;
  do not persist arbitrary Graphiti result payloads or prompts in PostgreSQL.
  Complete with matching current attempt only. If completion commit outcome
  is lost, do not claim success from the in-memory result; caller may read
  ledger state later, but MUST NOT redispatch uncertain work.
- Any exception after dispatch begins is conservatively uncertain, including
  validation failures, timeout, cancellation and lost acknowledgment. Attempt
  a bounded shielded uncertainty record with stable error codes; preserve the
  original cancellation semantics and never expose raw provider/SQL errors in
  public error text. If the recording itself fails, retain admission (running
  is also quarantined), raise a stable error and do not issue fail_no_effect.
- Explicit finite positive per-operation timeout with an upper bound; note that
  cooperative cancellation cannot prove a remote writer stopped. No automatic
  extraction retry, marker-absence retry or uncertain release. No claims of
  distributed exactly-once, stale-Neo4j fencing or durable result fact storage.
- Initialization/model configuration and actual spend authorization stay
  outside this coordinator. It is not exposed to UI or network in this slice.
