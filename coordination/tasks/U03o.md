## Driver and child contract

- Implement the accepted trusted driver protocol with a constructor-bound trusted
  picklable session factory, using multiprocessing spawn (no fork assumptions).
  Factory is executable host code, never accepted from JSON, paths or user data.
  Target bootstrap must have no eager native/provider imports. Do not create a
  plugin registry, import user module names or shell out to configurable commands.
- Bind one driver to one validated request/attempt; retain actual Process and
  private pipe handles in the owning instance. Reject mismatched run/attempt/child
  tokens before every command. Persisted PID alone never authorizes signalling.
  Unknown handles in a new driver instance return unknown/absent, never adoption.
- Child reports bounded ready identity after validating request and factory
  binding; launch returns promptly so coordinator can attach within its DB lease.
  Native work must wait for a one-time go command from the first observe call
  (coordinator only observes a durably running attempt). Repeated observations
  cannot start native work twice. Cancellation before go must not start it.
- Use bounded JSON byte messages with exact keys and identity checks. Use
  send_bytes/recv_bytes(maxlength), not pickle-based receive of worker messages.
  Bound handshake/receive/close/join durations and payloads. Reject malformed,
  oversized, duplicate/conflicting or wrong-identity terminal evidence. Never
  return raw exceptions, model outputs, credentials or artifact paths in control
  records. IPC messages carry only fixed status/identity and digest evidence.
- The spawned child must scrub inherited provider keys/proxies/startup hooks
  before calling any supplied factory/native code, preserving only explicit
  runtime necessities. Keep parent environment unchanged. Trusted model factory
  receives no credentials from these wire DTOs. Current tests use no paid clients.
  Any future live host must separately enforce configured secret/cap policy.
- Parent observes completed/failed only after a valid terminal message AND the
  exact owned child has exited successfully under the agreed protocol; process
  exit alone is not a valid completion. Session closes in child finally block.
  Crash/missing terminal message/lost ready/timeout retain uncertainty; no retries.
- cancel acts only on this driver's owned handle, bounded cooperative grace where
  practical then terminate/join (kill fallback only same created handle). Return
  cancelled only after observed termination; failure to prove exit is unknown.
  Cancellation proves termination of the owned process, not rollback of provider
  or database side effects. No budget release. Do not signal arbitrary saved PIDs.
- Provide explicit idempotent driver close that cleans up only its own handles,
  including partial launch failures. No global enumeration or cleanup. A parent
  crash cannot be claimed to guarantee child termination; document that limit.

Test-only factories may create deterministic model backends but production code
