Base1f3ba5e, branch task/u03-native-workflow, existing U03 worker in u03 only.
Implement only: no execution/imports/tests/builds/install/network/Git/audits.
Main owns review, full native runtime, checks, inherited hashes and CI updates.

## Usable deliverable

Extend the accepted provider-neutral preparation/report work into a real native
OASIS/CAMEL workflow: prepared Twitter/Reddit artifacts -> actual native agent
loading and bounded rounds -> action logs and actual native interview -> injected
report interview capability. Retain inherited algorithms/platforms, not a new
toy simulator. Main must be able to qualify this without paid models, Zep or
embedding downloads using explicit deterministic fake model/embedding dependencies.
No claim that fake responses establish live model quality or predictive accuracy.

Read accepted preparation_dependencies, report_dependencies, simulation_runner,
three native scripts, action_logger, simulation_ipc, native engine tests and
installed dependency source if present (read only). Identify actual injection
seams before editing; report any unavailable native contract rather than guessing.

## Scope and boundaries

- Owned backend/scripts/run_parallel_simulation.py, run_twitter_simulation.py,
  run_reddit_simulation.py, a new internal native dependency/lifecycle helper,
  narrow simulation_runner integration if required, focused backend/tests and
  backend/engine_tests source, architecture doc and handoff. No frontend, routes,
  SQL, Temporal/budget/Graphiti package or existing preparation/report semantics.
- Prefer shared dependency/lifecycle plumbing over duplicating native algorithms.
  Explicit trusted in-process dependencies only; never module-path/eval/CLI
  callback supplied by user data. A test fake is not a user-selectable production
  provider. Do not turn paid dispatch on. Preserve existing CLI compatibility.
- Make script imports safe for embedding: no unconditional dotenv load, model
  construction, network, monkeypatching builtins, env mutation or process startup
  merely from import. Move necessary legacy CLI setup into entrypoint. Ensure
  direct script invocation remains supported. Keep optional runtime imports lazy
  enough for lean backend tests; real native qualification uses installed engine.
- Inject model creation and, where required, local deterministic embedding or
  recommendation dependencies at legitimate native seams. Keep real native graph
  loaders, environment action execution, database records and IPC handlers.
  Do not mock entire agent/environment in the native integration proof.
- Bounded round count, deterministic explicit fixture seed, explicit lifecycle
  ownership, reliable async close on success/failure/cancellation. Completing
  rounds is distinct from keeping an interview environment alive. Avoid detached
  background work or unbounded waits. Use unique temporary paths in tests only.
- With Zep graph memory updates disabled, ensure this explicit neutral workflow
  never initializes Zep. Do not silently disable requested graph-memory writes or
  pretend they were persisted; neutral run-memory ingestion remains a separate
  unaccepted capability if not provided by an authorized adapter.
- Supply a trusted report interview adapter bound to exact simulation and
  platform/agent identity using actual inherited IPC/native interview methods.
  Reject missing/closed/wrong-scope/unknown agents explicitly; never invent an
  interview from persona text. Preserve batch/platform distinction and errors.
  No arbitrary exceptions/provider text persisted or returned in new neutral APIs.

## Source tests Main will execute

1. Cold lean import does not read dotenv, construct live SDKs, change builtins,
   start processes or connect. Legacy CLI and existing IPC tests remain intact.
2. Real native runtime loads artifacts from accepted preparation shape for both
   platforms, runs bounded rounds with deterministic injected model responses,
   produces real database/action-log effects, performs actual interview through
   real native handler and provides it to accepted report capability.
3. Prefer one complete offline vertical fixture using real preparation outputs
   and report agent where feasible. State exact boundaries if fixture does not
   yet include source ingestion/full UI; don't call fixture complete application.
4. Cancellation/failure/close cleanup, no post-close interview, invalid graph/
   simulation/agent rejection, no Zep fallback. Fake semantics cannot stand in
   for actual native execution; tests must fail if native calls are removed.
5. No paid calls/downloads or user files; Main supplies scrubbed env and existing
   locked native engine. Worker authors tests but runs nothing.

Return stable unverified source handoff. If native dependency limitations prevent
the entire deliverable, explain concrete blocker and retain useful implementation
without replacing native behavior or weakening qualification requirements.
