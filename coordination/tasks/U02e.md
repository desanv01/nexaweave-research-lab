## Contract

- Introduce frozen validated ParseLimits with finite integer bounds and defaults:
  max_file_bytes=50MiB, max_text_chars=5,000,000, max_pdf_pages=500,
  max_files=20, max_aggregate_chars=5,000,000. Reject bool/zero/negative or
  nonsensical types. Optional limits keyword on extraction methods; preserve
  positional compatibility and default results for valid existing documents.
- Check regular-file status without following links/reparse points before
  reading. Bounded reads max+1 detect growth; stable safe errors without raw
  source path or document text. Caller remains responsible for trusted root;
  this utility cannot eliminate local check/open races or hardlink risks.
- Read text in bounded bytes before encoding detection. Preserve existing UTF8,
  UTF8 BOM and UTF16 BOM/legacy encoding behavior (explicit BOM handling as
  needed). Reject decoded NUL/obvious control-character binary payloads, but
  allow normal newline/tab/CR and Unicode documents. Never silently truncate.
- For PDF require recognizable PDF header within first1024 bytes; reject
  encrypted/password-required and invalid format with safe classified errors.
  Bound page count before iteration, track aggregate text including separators
  incrementally and abort before appending text past max_text_chars. Empty or
  scanned PDF stays empty text, not fabricated OCR. Always close the document.
  Native fitz opening/one-page decoding can still consume time/memory: explicitly
  document that these limits are not process isolation or a hard memory cap.
- Stable parser exception types/codes distinguish size/limit, unsupported or
  malformed input without leaking filenames/paths/content. Preserve existing
  missing-file/unsupported errors where tests rely on category, not private text.
- extract_from_multiple validates count and aggregate characters including
  labels/separators. Do not swallow limit failures into a plausible successful
  combined document. Ordinary per-file parsing errors may retain the inherited
  failure marker behavior, but use bounded basename and safe error text, never
  the full source path or underlying exception message. No unbounded error text.
- split_text_into_chunks must validate integer chunk_size>0, integer overlap>=0
  and overlap<chunk_size (bool invalid). Bound input to5,000,000chars and emitted
  chunks to100,000; raise instead of silent truncation. Guarantee strict cursor
  progress even when sentence-boundary adjustment would cause end-overlap<=start.
  Preserve inherited sentence-aware boundaries for normal settings and preserve
  all non-whitespace content; no gaps when preventing non-progress. Empty input
  returns[], normal Unicode/multidocument inputs remain valid. No model calls.
