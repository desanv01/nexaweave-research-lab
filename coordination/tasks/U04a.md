## Data and repository contract

Trusted host supplies principal (existing printableASCII nonblank1..128),
workspace UUID, project UUID and display project ID (ASCII alnum/_/-1..128).
UUIDs are persisted explicitly, not guessed from legacy IDs. Principal is
authenticated by future host, not by this store or CLI user argument.

ProjectStore(connection_factory) with APIs:
- create(principal, workspace_id, project_id, display_id, snapshot, evidence=())
  -> immutable revision1 record; same full identity/content is idempotent,
  changed input under existing UUID or display binding -> fixed Conflict.
- get(principal, project_id, revision=None) -> revision/current record;
  unknown/wrong owner -> same fixed NotFound.
- list_projects(principal, workspace_id, limit=50) bounded <=200 current records,
  deterministic ordering. No unscoped listing.
- update(principal, project_id, expected_revision, snapshot, evidence=()) ->
  new immutable revision after exact CAS; stale version -> Conflict, never lost
  update. Concurrent same expected revision has one winner. No blind retries.
- history(principal, project_id, after_revision=0, limit=50) ordered bounded
  immutable revisions. No physical delete/ownership transfer in this slice.

Schema project rows own immutable principal/workspace/project/display identity
and current revision. Revision rows own revision integer>=1, bounded canonical
snapshot JSON, bounded evidence JSON, deterministic SHA256 digest and UTC
created_at. Use relational PK/FK/unique constraints, including owner/display
binding (within workspace) and (project_id,revision). Index actual owner/workspace
listing/FKs. Revision records never UPDATE on application paths; immutable
content-address digest verifies read/import content. Short transactions and row
locks/CAS only; no filesystem/provider calls while a transaction is open.

Snapshot is the inherited Project.to_dict JSON object with documented v1 field
allowlist, valid status, matching display project_id, bounded strings/numbers/
collections. Preserve all inherited fields, including files and legacy zep_* IDs
as inert metadata, not executable authority. Explicitly document file paths in
legacy snapshots are unresolved metadata; importing does NOT copy or access
them and does NOT prove binaries migrated. Do not normalize/drop content silently.
Cap encoded UTF8 snapshot+evidence at1MiB total; reject duplicate keys/nonfinite
JSON/depth>32/invalidUnicode in CLI input and reject invalid Python types before
connection. Do not use str/arbitrary-object coercion. Validate copied data.

Evidence manifest up to100 entries, exact fields: evidence_id UUID,
source_revision UUID, sha256 lowercase64hex, object_key nonempty bounded relative
opaque storage key (no absolute path, backslash, traversal/dot segments, URL or
control chars), byte_length integer0..50MiB. Unique evidence_id within revision.
These are declared references, NOT a claim that blobs were inspected/verified.
Preserve manifests across reads/export. Referential source objects and spans are
a follow-up; do not invent source text or assert content verification.

Explicit migrate(connection) creates mf_app with version/checksum/catalog-shape
verification. Separate advisory-lock key from mf_knowledge migration, bounded
statement/lock timeouts, fixed errors. No import/runtime automatic DDL, no
production migrations. Preserve foreign schemas. Reject unknown/drifted schemas
without destructive repair. Runtime needs no migration-owner rights.
