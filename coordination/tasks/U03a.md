## Data/API contract

Use fixed schema mf_knowledge, version/checksum migration record, and:

- scopes: group_id primary key (canonical KnowledgeScope.group_id), canonical
  scope JSONB, tombstoned boolean, created_at timestamptz. Same group with changed
  canonical scope is a conflict; derive group only from validated scope.
- operations: composite (group_id, operation_id UUID) primary key/FK scope;
  fingerprint 64 lowercase SHA256 hex; state enum-like CHECK pending/running/
  completed/uncertain/cancelled/failed_no_effect; created/updated timestamps;
  current_attempt UUID nullable, bounded receipt JSONB nullable, stable error_code.
- attempts: composite scope/operation/attempt UUID identity, FK operation,
  start/heartbeat/finish timestamps, outcome and stable error_code. Keep history.
- scope_admissions: group_id primary key/FK scope, operation/attempt composite
  FK attempts. At most one in-flight or uncertain writer per scope. Do not
  expire/delete admission from a clock or heartbeat alone.

Use application-generated UUID4 attempt tokens, parameterized SQL, explicit
bounded transactions, foreign-key indexes, no global connection or implicit
DDL-on-import. A Ledger takes a connection factory; each method obtains and
closes its own connection (no external network wait inside a transaction).
Methods: migrate(connection), register_scope(scope), admit(scope, operation_id,
fingerprint), get(scope, operation_id), claim(scope, operation_id),
heartbeat(scope, operation_id, attempt_id), complete(..., receipt),
mark_uncertain(..., error_code), fail_no_effect(..., error_code),
cancel_pending(scope, operation_id), tombstone_scope(scope).

Results are typed immutable dataclasses/models, errors stable dedicated types
(conflict, busy, stale attempt, invalid transition, tombstoned, not found).
No raw DB errors/DSNs/private payloads in public error text or logs.
Fingerprint helper accepts validated scope/source/ontology and uses the same
canonical request fields as existing provider._request_fingerprint; no divergent
idempotency identity. Validation before SQL must reject malformed fingerprints,
receipt shapes, timestamps and error codes; receipt capped 64KiB UTF-8 and includes
scope group_id, deterministic episode_id and fingerprint verified against the
operation. Receipt is metadata/evidence IDs only, not raw prompts/content/secrets.

## Transactions/state rules

Lock scope row before operation row consistently. Admit same identity/input
returns existing state; altered fingerprint conflicts. Claim only pending or
failed_no_effect, inserts attempt+admission and marks running in one transaction.
If any different admission exists, raise busy; same operation already running
returns busy, never returns a token authorizing a second dispatcher. Complete/
heartbeat/failure require matching current attempt and admission. Completion
stores validated immutable receipt and releases admission atomically. Duplicate
complete with identical receipt/current attempt may return existing completion;
different receipt conflicts. mark_uncertain retains admission. fail_no_effect
releases only a running attempt with explicit no-effect classification; never
allow uncertain -> retryable from that generic method. Pending cancellation
affects pending only; running work cannot be rolled back by flag changes.
Tombstone blocks new admission/claim but lets an existing matching attempt record
its completion/uncertainty for later cleanup. No automatic replay or distributed
exactly-once claim. Reconciliation is a future explicitly reviewed API; do not
provide a generic force_reset, drop, purge or unlock method.

Migration runs explicitly on an empty disposable schema; use transaction-scoped
advisory lock for migration serialization and checksum validation on rerun. Do
not hide existing table/schema mismatch with IF NOT EXISTS. No production role
creation or destructive downgrade. Document migration-owner vs runtime privileges
without embedding credentials or granting unrestricted database rights.

## Write test sources; Main executes

Pure validation/state DTO tests. Real PostgreSQL opt-in fixtures require
KNOWLEDGE_POSTGRES_INTEGRATION=1 and fixture-only DSN; skip otherwise. Unique
scope/operation per case, real separate connections/threads for concurrency.
Exercise duplicate/different admission, competing claims same/different op,
independent scopes, rollback on conflict, stale tokens, uncertain retained lock,
no-effect retry with new token, pending-only cancel, tombstone during running,
duplicate/different completion receipts, checksum mismatch migration rejection,
fresh Ledger instance state visibility. Use finite ThreadPool futures/timeouts,
no unbounded sleeps. A fake provider wait is not a database-transaction test unless
another real connection can access relevant rows during that wait.
