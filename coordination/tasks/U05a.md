## Contract decisions

- New mf_execution schema, explicit migration function with checksum/catalog
  drift detection and transactional rollback consistent with existing stores.
- Owned budget account: canonical UUID, principal/project matches existing
  ProjectStore; immutable explicit positive USD-microunit cap. No float money,
  bool integers, negative/overflow values, mutable currency or implicit defaults.
- Unique account + operation identity and request fingerprint. Reservation reuse
  with identical parameters is idempotent; changed fingerprint/ceiling conflicts.
- Reserve atomically under account row lock after checking available balance.
  Parallel reservations cannot oversubscribe; lock order consistent; SQL parameter
  binding, short transactions/timeouts, no network/model awaits while locked.
- State transitions reserved -> started -> settled or uncertain. Release only a
  provably undispatched reserved attempt, with ownership/attempt fencing. Started
  or uncertain never auto-release on timeout, cancellation, restart or lease age.
  Do not auto-retry uncertain external effects. Duplicate callers must not both
  win start/dispatch. Use attempt identity to reject stale settlement/release.
- Successful guarded ingestion conservatively accounts the full authorized
  reservation ceiling, explicitly labeled accounted ceiling, not measured cost.
  Keep actual_usage unknown unless trustworthy usage is supplied in a later stage.
  Remaining=cap-accounted-unsettled-reservations (uncertain remains reserved).
- Durable receipt: validated scope/episode/fingerprint/evidence from coordinator;
  duplicate settled workflow can return the saved receipt without another dispatch.
  Record fixed error/status codes only, never credentials/source content in budget
  rows or logs. Preserve cancellation propagation after marking uncertainty.
- No reset, override, expiry-release or admin reconciliation route in this slice.
  Expose state so future explicit reconciliation can use real evidence.
