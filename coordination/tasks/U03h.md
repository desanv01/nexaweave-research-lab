## Migration integrity

Generalize explicit migrate(connection) to ordered versions1,2. Never rewrite
0001 SQL or the existing version1 record on upgrade. Maintain transaction-level
advisory migration lock, catalog-only search_path and bounded SQL/lock timeouts.
No auto migration at import or runtime method call; caller supplies explicit
migration-owner connection separately from runtime connection factory.

On existing schema verify ordered contiguous known versions (no gaps, unknown
future versions, bad checksum, missing migration record), every applied SQL
checksum, and current schema against the latest applied schema_checksum BEFORE
adding pending migration. On v1 verify current v1 shape before upgrading. Apply
each pending SQL and persist that version's post-migration shape fingerprint in
the same atomic transaction. On v2 verify latest shape, not the historical v1
shape against v2 tables. Fresh installs apply both atomically. Failed upgrade
rolls back all effects; no opportunistic IF NOT EXISTS masking drift, no delete,
recreation or repair of existing data. Fixed MigrationMismatch/StorageError,
never database diagnostics in public exception text. Downgrade unsupported.

Table mf_knowledge.scope_bindings:
- principal text nonempty, <=128 ASCII printable characters, not whitespace-only;
  exact same principal identifier domain as current command dispatcher.
- display_graph_id text ASCII letters/digits/underscore/hyphen length1..128.
- group_id text NOT NULL FK scopes(group_id), UNIQUE (initial single owner/name
  per complete logical scope; no aliases or ownership transfer in this slice).
- created_at timestamptz NOT NULL default now().
- primary key (principal, display_graph_id); constraints enforce ID domains;
  UNIQUE group_id index also supports the FK. No extra credentials, prompts or
  duplicated canonical-scope JSON; join the existing authoritative scopes row.

Same display ID may exist for different principals only if mapped to distinct
scopes. Reusing any binding for a different scope or owning an already-bound
group under another principal/name is Conflict, never update/upsert overwrite.
No delete/rebind/transfer endpoint. Tombstoned bindings remain reserved.

## Library contract

ScopeBindingStore(connection_factory), frozen BindingRecord(principal,
display_graph_id, scope:KnowledgeScope, created_at). Return validated/copy-safe
scope; no mutable caller references affecting persisted mapping. Use the existing
short bounded transaction helper and fixed ledger errors. No network/provider
calls, environment reads, SDK creation, or logging of inputs/DSNs.

bind(principal, display_graph_id, scope) -> BindingRecord:
- Privileged provisioning operation for a trusted host only, NOT an API granting
  ownership from caller-supplied scope. Validate inputs and revalidate scope
  copies before connection. Do not derive scope UUIDs from display IDs.
- In one short transaction register/lock canonical scope via existing Ledger
  scope helper, reject tombstones/mismatched canonical data, insert only if no
  conflicting key/group, then verify exact immutable tuple. Same tuple is
  idempotent and preserves original created_at, across fresh store instances.
- Concurrent identical calls return same record; competing binds have one
  durable winner, losers fixed Conflict, no orphan newly-created scopes on
  failed transaction. Preserve other tenants and unrelated records.

resolve(principal, display_graph_id) -> BindingRecord:
- Principal must be host-authenticated identity, never a public request field.
- Lookup only exact composite key; unknown and wrong-principal -> fixed NotFound.
- Join/revalidate stored canonical scope and recomputed group_id; malformed or
  mismatched persisted data fails fixed Conflict, never invent/recover scope.
- Reject tombstones using existing Tombstoned; no fallback to Zep or scope ID
  hashing/guessing. Check persisted row principal/display ID/basic types/date.
- Does not grant roles or guarantee read safety after its short transaction;
  active/uncertain-write read admission and cross-page consistency remain next
  separate contracts. Do not hold a PostgreSQL lock across a provider call.

All SQL values parameterized; only fixed owned identifiers. Expected constraint
conflicts map Conflict without SQLSTATE/constraint/other-principal leakage;
unrelated DB failures map StorageError. Preserve KeyboardInterrupt/SystemExit.
No broad recovery from unexpected programmer errors disguised as NotFound.
