## Data and authority

1. Immutable bounded request identifies principal, project UUID + pinned positive
   revision, simulation ID, native run UUID, prepared artifact manifest SHA256,
   runtime/config fingerprint SHA256, enabled platforms, seed and max rounds.
   Match existing native limit1..24. Use canonical digest of validated immutable
   fields as semantic request identity. Reject unknown wire keys/malformed values;
   no secrets/source text/model responses/commands/module paths/raw filesystem
   paths or arbitrary metadata in this control record. Host remains responsible
   for computing artifact digests from authorized artifacts; supplied digest is
   not proof a file was read. No HTTP endpoint or user-controlled driver.
2. Authorize principal against exact stored project revision, not current/latest.
   Persistent uniqueness on run UUID and (project UUID, simulation ID) prevents a
   second run ID from resetting the same simulation. Identical registration is
   idempotent; different fingerprint/ownership/revision is conflict/denial. Return
   fixed safe errors, do not expose another principal's record existence/content.
3. Distinguish declared, starting, running, completed, failed, cancelled, uncertain
   states and separately recorded cancellation intent. A single atomic transition
   declared->starting creates one attempt UUID and binds an owner-instance UUID.
   Only the first successful transition grants launch permission. Repeating a
   request, lost response, timed-out call or identical owner MUST NOT grant a
   second permission. Terminal/uncertain states never go back to declared.
4. Persist starting BEFORE external launch, with finite lease from DB time. A
   launch/ack uncertainty retains that durable fence. Bind observed native child
   identity to run/attempt/owner using an opaque instance UUID plus bounded
   process identity metadata; PID alone is not ownership. Do not implement kill
   by arbitrary saved PID, OS process enumeration, automatic adoption or restart.
5. Heartbeats/transitions use compare-and-set current state + exact attempt and
   owner tokens. Database clock is authoritative; lease seconds bounded. Expired
   owner cannot extend/revive/complete the run. Explicit reconciliation fences
   expired starting/running as uncertain; no lease takeover/relaunch even if the
   process appears absent. A new coordinator reading a completed row can recover
   the recorded receipt without invoking the driver. Cancellation intent alone
   does not prove termination or release any budget.
6. Receipt is bounded fixed-shape identity/status evidence from trusted driver,
   with matching run/attempt/instance/fingerprint. Wrong/stale/partial receipts
   cannot complete a run. Completion and duplicate matching receipt persistence
   are idempotent; conflicting terminal receipt fails closed. No full provider
   usage/invoice accounting claim. No changes/releases in BudgetLedger.

## Trusted coordinator and SQL rules

Coordinator has bound principal, fresh owner-instance UUID, store, explicit
trusted driver, and dispatch policy callback default OFF. Its start path validates
and registers, obtains one launch permission, invokes driver outside transaction,
records exact returned identity; any ambiguous launch/DB acknowledgement error
leaves/fences uncertainty, never retries. Cancellation and observation similarly
use current owned attempt and retain uncertainty on unknown child status. Do not
hold locks over await, file I/O, process calls or sleep. Offload synchronous DB
operations if async coordinator methods are used. Driver protocol must make
unknown/absent/running/terminal distinctions explicit and avoid broad raw errors.

Main applied PostgreSQL skill short-transactions/consistent-lock-order guidance:
short bounded transactions, qualified schema names, parameterized values, finite
statement/lock/idle-in-transaction timeouts, deterministic lock order and indexes
matching identity/expiry queries. SQL constraints reinforce immutable identity,
allowed states and receipt/state consistency. No unbounded list/scan API or schema
drift acceptance. Migration mismatch must be fixed safe error.
