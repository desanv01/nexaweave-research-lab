## Design requirements

- Add explicit trusted neutral construction, leaving default legacy behavior.
  No imported/constructed Zep SDK, client, credentials or retry helper in neutral
  mode, including error paths. Defer legacy imports or use type-only annotations.
  Model abstraction is injected existing chat/chat_json interface, no SDK/key
  read as side effect. Use explicit None checks, not falsey fallback.
- Reuse existing InsightForge/Panorama/QuickSearch algorithms over neutral read
  primitives (an adapter/subclass or primitive interface), not copy/rewrite rich
  methods. Existing DTO imports must remain compatible. If subclass used, ensure
  inherited methods cannot touch an uninitialized legacy client in neutral mode.
- Bind one authorized facade graph projection per report construction, as with
  accepted preparation. Nodes/edges/temporality/provenance must come from that
  bounded accepted projection. Reject graph mismatch and unknown IDs. Do not mix
  changing projection A/B between prompt facts, related entities and evidence.
- Semantic search remains an explicit trusted, graph-bound injected capability.
  Define a small bounded result selection contract (IDs/scores over the captured
  projection, not arbitrary model-authored fact strings). Validate duplicates,
  unknown IDs, scope/kind, limits, malformed/nonfinite scores; resolve content
  and evidence from the accepted projection. No implicit lexical substitute or
  Zep fallback. Missing capability is fixed unsupported, never empty success.
  No live adapter/bootstrap is claimed by this task; fixtures are deterministic
  search selections, NOT demonstrated semantic quality. Report this remaining
  runtime connection clearly in docs and metadata.
- Bind simulation identity separately for interviews. Preserve the existing
  real legacy interview flow unchanged. Neutral mode requires explicit trusted
  interview capability or reports unsupported; never synthesizes interview
  answers via ordinary report LLM or silently opens native IPC. Wrong simulation
  ID must be rejected before capability invocation. Do not present source graph
  facts alone as observed simulated events or opinions.
- Preserve evidence IDs and original graph layer/scope in a bounded retrieval
  ledger/sidecar for the actual report, separate from generated prose. Recording
  retrieval evidence is NOT claim-level citation validation: say so. Include
  neutral capability/limitations metadata so fixture or missing capabilities
  cannot be mistaken for a fully connected simulation report.
- New neutral failures must not expose exception/provider secrets in outward
  responses, persisted report/error state or report logs. Existing high-level
  catch-and-continue logic may need a narrow strict-neutral branch: capability
  and authorization failures cannot yield falsely COMPLETED report. Prefer
  explicit failed/not-ready status; no silent fallback to ungrounded generation.
- Bound tool calls/subqueries/results using existing limits plus validated
  neutral inputs. No retries of paid calls introduced. New trusted helper is
  internal only, no HTTP path or live model bootstrap enabled. Budget remains
  host responsibility; all execution for acceptance uses scripted clients.
- Preserve existing safe report paths, progress, artifacts and default legacy
  behavior. No global filesystem migration or claim of atomic publication.
