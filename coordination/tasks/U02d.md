## Bounded scope

The inherited Flask factory enables wildcard CORS and logs parsed JSON bodies.
Replace those two behaviors without changing business API handlers, model
providers, native engine behavior or the frontend. This is NOT authentication,
tenant ownership, CSRF protection for arbitrary cookie credentials, or public
deployment readiness. No new dependency, environment installation or network.

Allowed files: backend/app/__init__.py, backend/app/config.py, new
backend/app/utils/browser_origins.py, backend/tests/test_browser_boundaries.py,
docs/security/browser-boundaries.md, coordination/handoffs/U02d.md.
Main owns manifest, integration/CI, ledger and review records.

## Contract

- Replace wildcard CORS with an explicit startup-validated origin allowlist,
  configured via MIROFISH_ALLOWED_ORIGINS (comma-separated) or config class
  override. Defaults: http://localhost:3000 and http://127.0.0.1:3000, the
  inherited Vite development origins. Empty explicitly disables cross-origin
  access; preserve normal no-Origin API clients and Vite proxy requests.
- Parse an origin as scheme + host + optional port only. HTTP/HTTPS only;
  reject wildcard/regex, null, userinfo, path/query/fragment, CRLF/whitespace,
  malformed port and missing host. Do not silently repair suspicious input.
  IPv6 bracket origins should be accepted if well formed. Document any stricter
  ASCII hostname limitation. Reject bad config during startup before hooks or
  simulation cleanup registration; never echo raw config secret-like strings.
- The allowlist must enforce exact origins, not regex matches. flask-cors may
  interpret strings as regex: use escaped anchored compiled patterns or another
  explicitly exact approach. Never reflect an arbitrary request Origin. Do not
  dynamically trust Host, X-Forwarded-Host or a user-supplied provider endpoint.
- For /api/ and its OPTIONS preflights, an Origin header not exactly permitted
  is rejected with stable JSON403 before handlers run; no-Origin clients still
  work. Reject 'null', comma-combined/malformed origins, prefix/suffix lookalikes
  and scheme/port differences. Allowed requests get exact CORS origin and
  Vary: Origin, allow only actual API methods GET/POST/PUT/PATCH/DELETE/OPTIONS
  and allowlisted Content-Type/Authorization headers. Credentials false; no
  wildcard credentials or arbitrary-header reflection. OPTIONS preflight must
  not invoke business mutation handlers. Preserve status/body of allowed calls.
- Health stays a minimal no-secret endpoint. Do not invent login/security
  claims from this origin check: non-browser callers can omit/spoof Origin.
- Request logging must never parse/log JSON bodies, query strings, raw paths,
  headers or credentials. Log method plus registered endpoint identifier and
  response status only. Unmatched endpoint gets a fixed label. Preserve useful
  startup logs. Do not claim all existing route/service exception logs sanitized;
  those remain separate work. Avoid changing stable inherited API error shapes.

## Test source and handoff

Use actual create_app/test client with fake business fixture endpoints, no
models or external services. Prove allowed exact origins/preflights and Vary;
disallowed origin never invokes side effects; no-Origin request preserved;
empty allowlist; malformed config before app cleanup registration; IPv6 and
scheme/port/prefix/suffix/regex/null edge cases; unsupported requested headers
not granted; no credentials flag; health unaffected. Capture actual logger calls
or caplog with sentinel secret in JSON/query/header/path and verify no request
body parsing for logging (authorization/API validators may parse separately).
Use clear distinction between CORS browser permissions and server-side rejection.
Document configured development origins and how future trusted deployment
origins are explicitly configured. Handoff is unverified; run no commands to
check/test/build/audit or perform Git operations.
